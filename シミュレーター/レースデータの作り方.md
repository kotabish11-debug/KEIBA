# シミュレーター用レースデータの作り方

重賞(G1・G2・G3、障害重賞を含む)の出走馬が登録されたら、このルールでレースデータを作る。
シミュレーター(https://claude.ai/artifact/P8QScqCpR36cPEkxMtou9s)は、届いたレースを自動でレース一覧に追加する。

## 1. 保存先
- ファイル: `シミュレーター/races/<レースID>.json`(1レース1ファイル、UTF-8)
- レースID: 英小文字と数字のみ。`<レース名のローマ字><年>`。例: `kikkasho2026`(菊花賞)、`artemis2026`(アルテミスS)、`tokyohj2026`(東京ハイジャンプ)
- シミュレーターへの反映: 同じ内容を ArtifactData で `races/<レースID>` に書く(手順は「4. シミュレーターへの書き込み」)

## 2. いつ作り、いつ直すか

| 段階(stage) | タイミング | やること |
|---|---|---|
| 特別登録 | 前週の日曜夜 | 登録馬全頭でファイルを作る。騎手が未定なら `"jockey": "未定"` |
| 出走確定 | 木曜〜金曜 | 出走しない馬を外し、騎手・斤量を確定の値にする |
| 枠順確定 | 木曜〜金曜 | `umaban` を入れる |
| 当日 | 当日朝〜発走 | `odds`(実オッズ、`oddsKari: false`)・`weight`・`weightDiff`・`going`・`scratched` を更新 |
| 結果確定 | レース後 | `stage` を「結果確定」にし、`result` に1〜3着の馬名を入れる |

能力値(実績〜騎手)は、特別登録か出走確定のときに付け、そのあとは大きな変化(乗り替わり・取消・馬場悪化)があったときだけ直す。

## 3. JSONの形

```json
{
  "id": "kikkasho2026",
  "name": "菊花賞",
  "grade": "GI",
  "date": "2026-10-25",
  "place": "京都",
  "no": 11,
  "time": "15:40",
  "surface": "芝",
  "dist": 3000,
  "dir": "右",
  "courseNote": "外回り",
  "cond": "3歳牡・牝 馬齢57kg",
  "stage": "出走確定",
  "chaos": 8,
  "weather": "晴(予報・降水10%)",
  "going": null,
  "updatedAt": "2026-10-23T18:30:00+09:00",
  "source": "スポーツナビ競馬・JRA・tenki.jp",
  "memo": "出走馬確定。枠順は金曜に発表",
  "horses": [
    {
      "name": "ロブチェン", "jockey": "松山弘平", "style": "先行",
      "jisseki": 92, "kyori": 78, "course": 80, "choshi": 85, "kishu": 88,
      "heavy": 0, "odds": 2.8, "oddsKari": true, "umaban": null,
      "note": "皐月賞・ダービーの二冠。神戸新聞杯も勝利。3000mは初めて。"
    }
  ]
}
```

- `grade`: `GI` / `GII` / `GIII` / `J・GI` / `J・GII` / `J・GIII`
- `surface`: `芝` / `ダ` / `障`。`courseNote`: `内回り` / `外回り` / 空文字
- `going`: 芝(障害は芝)の馬場。0=良 1=稍重 2=重 3=不良。未発表は `null`
- `chaos`(波乱度・省略可): G1は8、G2・G3は8.5、ハンデ戦と2歳戦は9.5、障害は9
- `courseBias`(脚質ごとの加点。例 `{ "逃げ": 0, "先行": 1, "差し": 0.5, "追込": -1 }`)・`drawBias`(内枠の有利さ。0=なし、0.8=内枠がかなり有利、マイナスは外枠有利)は、判断材料ファイル(`馬情報/*_判断材料.md`)の過去10年の傾向から決めて必ず入れる。判断材料がまだ無いときだけ省略してよい(シミュレーターがコースの形から決める)
- 出走取消は、馬を消さずに `"scratched": true` を付ける

## 4. 能力値の付け方(各0〜100)

まずメンバーの中での順位を意識する。同じレースの中で差がつくように付ける。

| 項目 | 重み | 基準 |
|---|---|---|
| 実績 `jisseki` | 35% | G1勝ち 90〜95 / G1で2〜3着・G2勝ち 85〜89 / G2・G3で2〜3着・G3勝ち 78〜84 / OP・L勝ち、重賞で掲示板 70〜77 / 3勝クラス勝ち 62〜69 / 2勝クラス以下 50〜61。2歳戦は、新馬・未勝利勝ち 65前後、1勝クラス・OP勝ち 72前後、重賞勝ち 82前後 |
| 距離 `kyori` | 15% | 同じ距離(±200m)で勝利・重賞好走 85〜90 / 経験があり好走 75〜84 / 未経験だが血統・走りから見込める 65〜74 / 大幅な延長・短縮で不安 45〜64 |
| コース `course` | 15% | 同じコースの重賞で好走 85〜 / 似たコース(小回り・直線の長さ・右左回り)で好走 75〜84 / 未知 65〜74 / 合わない 50〜64 |
| 調子 `choshi` | 20% | 前走勝ち・好時計・上昇中 85〜95 / 前走好走(5着以内) 70〜84 / 前走凡走 55〜69 / 大敗続き、または6か月以上の休み明け 40〜60 |
| 騎手 `kishu` | 15% | リーディング上位・G1常連(ルメール、川田、武豊、戸崎、坂井、松山、岩田望、横山武、短期免許の外国人トップ騎手など) 85〜95 / 重賞常連 75〜84 / 中堅 65〜74 / 若手・減量騎手 55〜64。障害は障害リーディングで同様に付ける |

- コース・ローテの規則性(詳しくは [競馬場の特徴_JRA10場.md](../馬情報/競馬場の特徴_JRA10場.md) の「コースを読む6つの規則性」)
  - `course`: 今回と同じ回り(右・左)で好走がなければ -5、好走が逆の回りに偏っていれば -8。平坦コースでしか好走がなく今回が急坂(中山・阪神・中京)なら -5
  - `course`: 好走した舞台と今回の舞台のタイプ(広さ・コーナー・坂・直線の長さ。4グループは競馬場の特徴_JRA10場.md)が違えば、その分を割り引く。例: 小回りで器用さを生かして好走 → 今回は大箱 -3
  - `course`: 1コーナーまでの距離の向き不向き。前走、同じ場の短い方(例: 中山芝1800)で届かなかった差し馬が長い方(中山芝2000)に出るなら +3、その逆で粘れなかった先行馬も +3
  - `jisseki`: 関西馬(調教師が栗東)が関東の競馬場へ遠征するなら +2。前走までの好走が関東ローカル(新潟・福島)中心の馬が関西メイン(京都・阪神)の重賞に出るなら -3(人気になっていれば特に注意し、`note` に書く)
  - `choshi`: 前走が関西メイン(京都・阪神)の重賞で凡走でも、着差が小さく今回が格下の場なら、前走凡走の基準より +5 してよい
  - `drawBias`: 芝スタートのダート(東京ダ1600・中山ダ1200・阪神ダ1400・阪神ダ2000・京都ダ1400・中京ダ1400・新潟ダ1200・福島ダ1150)は外枠有利なのでマイナスにする。判断材料の馬番データと食い違うときは判断材料を優先する
- 危険な人気馬と巻き返し(詳しくは [危険な人気馬と単勝の狙い方.md](../馬情報/危険な人気馬と単勝の狙い方.md))
  - `choshi`: 前走逃げて好走 -2(同型がいれば -4)/ 半年以上の休み明け -9(通常の休み明けは -6)/ 前走道悪で好走して今回良馬場 -3(逆は +2)/ 芝で内枠→外枠、ダートで外枠→内枠で、前走好走 -3(逆の替わりで前走凡走なら +2)
  - `jisseki`: ダートで前走牝馬限定 → 今回牡馬混合の牝馬は -3(逆に、混合で負けて牝馬限定に戻るなら +2)
  - 前走4〜6着の馬は、前走1〜3着との差を付けすぎない(前走1〜3着は人気が出すぎやすい)
  - `choshi`: 着順だけでなく着差も見る。4着以下でも勝ち馬と0.3秒差以内なら +4、2〜3着でも1秒以上離されたら -4。負けた相手が強かったか(勝ち馬のその後)も見る
  - `jisseki`: タイム指数を使うときは近走の平均ではなく最高値で力の上限を見て、1〜2の差は同じとみなす
  - 2・3着が極端に少なく、勝つか大敗かの馬は `note` に「勝つか大敗か」と書く(単勝向き)
- 使わない情報(ノイズ。詳しくは [予想で捨てる情報.md](../馬情報/予想で捨てる情報.md))
  - `kishu`: 数年分の成績で条件ごとに差がはっきりしている騎手は [騎手の得意・苦手.md](../馬情報/騎手の得意・苦手.md) で調整する(例: ルメールは芝1200m前後・追込・高齢馬で下げ、東京芝2400mで上げる。ほかに高杉吏麒・田辺裕信・西村淳也・今村聖奈・幸英明・丹内祐次・松山弘平・北村友一・坂井瑠星・横山典弘・津村明秀・三浦皇成・武豊。追込馬に西村淳也・丹内祐次、芝1200mに田辺裕信、1番人気の幸英明は下げる)
  - `kishu`: 騎手の「最近の調子(ここ数週の勝ち星)」では上げ下げしない。乗り替わりの強化・弱化もオッズに織り込まれるので、基準どおりに付けるだけにする。例外: 以前その馬で好走した騎手に戻る(手戻り)なら +3
  - 馬体重: 増減だけでは動かさない(大きく動くと嫌われてオッズが上がり、単勝回収値はむしろ高い)。割り引くのは -20kg以上(`choshi` -4)・2〜3歳のマイナス2桁(-2)・夏や滞在競馬(北海道・小倉)での減少(-1)・6歳以上の+10kg以上(太め残り -2)だけ。2〜3歳の増加は成長として減点しない。大きく増減したときは、好走したときの馬体重に近いかを見て `note` に書く(近ければ心配いらない)。長距離輸送で減るタイプかも過去の遠征で確認する。休み明けの大幅増でも、休み前に減り続けていたなら「戻しただけ」として減点しない
  - 馬格: 大きい馬ほど成績が良い(400kg未満の複勝率約7%、500kg台は約25%)。`jisseki` を 420kg未満 -2・500kg以上 +1
  - 当日のパドック解説・SNSの評判では能力値を変えない。パドックを使うのは「入れ込むと走らない馬」など、その馬の過去のパドックと結果から事前に決めた条件に当てはまったときだけ
  - 他人の予想(予想サイト・SNS・YouTube)の印や買い目は能力値に入れない。参考にするのは、その結論に至った理由(展開・適性の見立て)だけ
  - 調教: 「好時計」「絶好調」だけでは上げない。その馬のこれまでの追い切りと比べてはっきり良い・悪いときだけ `choshi` ±2(新馬戦の加速ラップ +3 は別)。美浦の坂路は2023年10月に改修されたので、それより前の時計とは比べない([馬の走り方と調教.md](../馬情報/馬の走り方と調教.md))
  - 前走の中身: 着順より、メンバーの強さ・ペース・位置取りを見る。スローペースを2番手で楽に残しただけの好走は `choshi` -2、ハイペースで外を回されながら着差が小さい凡走は +2(着差の補正と合わせて±5まで)
- ダート(詳しくは [ダートの見方.md](../馬情報/ダートの見方.md))
  - 前の馬の砂をかぶるかを見る。内枠の差し・追込で、過去に内枠で砂をかぶって凡走しているなら `choshi` -2。内枠でも、通過順・前半3ハロン・スタートのうまさでダッシュ力があると分かる逃げ・先行は減点しない
  - 3勝クラス・オープン・重賞では先行争いが激しくなるので、内枠や馬群の中で砂をかぶっても好走したことがある差し馬は `choshi` +2
  - 道悪は砂が舞わずスピードが出るので、芝でも走れる血統・スピード型を `heavy` で +1 寄りにする。良馬場はパワー型
  - 中京ダ1800は例外で内枠有利(シミュレーターのコース別の設定に入っている)
- 2歳戦・キャリアの浅い馬(詳しくは [新馬戦の見方.md](../馬情報/新馬戦の見方.md))
  - `choshi`: 1〜3月生まれ +3、6月以降生まれ -3(`profiles` の `birth` で確認)。最終・1週前追い切りが加速ラップなら +3
  - `jisseki`: 新馬戦は、ダート500kg以上 +3・460kg未満 -3、芝460kg未満 -2。兄姉がJRAの新馬戦で好走していれば +2
  - `kishu`: 新馬戦で成績の良い騎手×調教師のコンビなら +3
  - 脚質: 新馬戦で戦績がないときは、陣営コメントの「スタートが速い」「前向きな気性」で `先行` にする(新馬戦は前が有利)
- 血統の国別タイプ(詳しくは [血統の系統と国別タイプ.md](../馬情報/血統の系統と国別タイプ.md))
  - 2・3歳限定の新馬・未勝利・1勝クラスのダート1400m以下で父が米国型なら `course` +2(全レース自動計算も同じ)
  - 古馬混合の芝2200m以上の重賞で道悪のときは、父・母父が欧州型の馬を `heavy` +1 寄りにする(道悪の実績がはっきりある馬は実績を優先)
  - 雨で重い芝でも、小回り・直線が短く前残りになりそうなとき(福島芝2000mの重賞など)は、母父が米国型の馬を `heavy` +1 寄りにする
  - 直線が短く坂があり上がりがかかるコース(中山金杯・福島牝馬Sなど)では、サドラーズウェルズ系・ロベルト系を持つ人気薄を `note` に書いて穴の候補にする
  - 当日の芝で、父がサンデー系以外の馬ばかり好走しているときは「反主流の馬場」と見て、日本型の人気馬を過信しない(当日バイアスと同じく `courseBias` の考え方で、能力値は±2まで)
- 展開の目印(省略可、詳しくは [展開予想の手順.md](../馬情報/展開予想の手順.md)): 近3走で2回以上1角先頭の「逃げないと走らない馬」は `"mustLead": true`、前走より200m以上の延長で逃げ・先行の馬は `"fromShort": true`。シミュレーターのペースの自動見積もりに使われる
- 脚質 `style`: 近3〜4走の4コーナー通過順で決める。ほぼ先頭=`逃げ`、頭数の前3割=`先行`、中団=`差し`、後方3割=`追込`
- 重馬場 `heavy`: 道悪で勝ち・好走 +2 / やや得意 +1 / 不明・普通 0 / やや苦手 -1 / 道悪で大敗 -2。道悪の経験が2戦以下なら、父の道悪適性([種牡馬の道悪適性.md](../馬情報/種牡馬の道悪適性.md))で ±1 する(全レース自動計算も同じ)
- 仮オッズ `odds`(`oddsKari: true`): 実績と前評判から人気を想定して付ける。全頭の(1÷オッズ)の合計が1.25前後になるようにする。実オッズが出たら置き換えて `oddsKari: false`
- 根拠 `note`: 能力値の根拠を1〜2文(主な実績・前走・不安点)。人気薄(仮オッズ・実オッズで10番人気以下)も後回しにせず、同じ手間で好走の要素(過去に好走した条件・血統・得意な馬場・騎手との相性)を探して書く。穴馬は印のない馬から出る

## 4-2. 馬カード用のデータ(`profiles`)
シミュレーターで馬名を押すと開く「馬カード」(血統・戦績)は、次の2つから作られる。
- ページと一緒に公開している `data/profiles.json`(PCで `シミュレーター\build_profiles.ps1` を実行すると、「馬情報」の `*出走馬*.md` と重賞の全着順から作り直せる。反映にはシミュレーターの再公開が必要)
- レースデータの `profiles`(下の形)。ここに書けば再公開なしでカードに出るので、出走馬ファイルを作ったら必ず付ける

```json
"profiles": {
  "ドリームコア": {
    "sexage": "牝3", "trainer": "田中博康(美)", "sire": "キズナ", "dam": "ノームコア", "damsire": "ハービンジャー",
    "birth": "2023-02-05", "owner": "吉田勝己", "breeder": "ノーザンF", "record": "7戦3勝[3-1-2-1]", "prize": "1億3240万",
    "comment": "重賞は桜花賞以外すべて3着以内",
    "runs": [
      { "date": "2026-09-06", "race": "紫苑S", "grade": "GII", "place": "中山", "surface": "芝", "dist": 2000,
        "rank": 3, "heads": 11, "pop": 1, "odds": 2.5, "jockey": "ルメール",
        "weight": 502, "weightDiff": 4, "time": "2:03.8", "pass": "4-4-5-3", "f3": 36.7 }
    ]
  }
}
```
- キーは馬名(`horses` の `name` と同じ表記)。分からない項目は省く。`runs` は新しい順で、近3〜5走
- 騎手カード(騎手名を押すと開く)は、`2026重賞_全着順.csv` から集計する。CSVを更新したら `build_profiles.ps1` を実行して再公開する
- 秋華賞(`shukasho2026`)のように `update` で書くレースでも、`profiles` は `horses` と別の項目なので、自動更新で消えない

## 5. シミュレーターへの書き込み
- ArtifactData を使えるときは、`url: https://claude.ai/artifact/P8QScqCpR36cPEkxMtou9s`、`collection: races`、`doc_id: <レースID>` に、JSONファイルの中身を書く
  - 新しいレース: `set`(`if_version` なし)
  - 既存のレース: 先に `get` して `version` を確認し、`set` に `if_version` を付ける
- 使えないときは、JSONファイルの保存だけでよい(PC側の同期のときに書き込まれる)
