# シミュレーター用レースデータの作り方

重賞(G1・G2・G3、障害重賞を含む)の出走馬が登録されたら、このルールでレースデータを作る。
シミュレーター(https://claude.ai/artifact/P8QScqCpR36cPEkxMtou9s)は、届いたレースを自動でレース一覧に追加する。

## 1. 保存先
- ファイル: `シミュレーター/races/<レースID>.json`(1レース1ファイル、UTF-8)
- レースID: 英小文字と数字のみ。`<レース名のローマ字><年>`。例: `kikkasho2026`(菊花賞)、`artemis2026`(アルテミスS)、`tokyohj2026`(東京ハイジャンプ)
- シミュレーターへの反映: 同じ内容を ArtifactData で `races/<レースID>` に書く(手順は「4. シミュレーターへの書き込み」)

## 2. いつ作り、いつ直すか

| 段階(stage) | タイミング | やること |
|---|---|---|
| 特別登録 | 前週の日曜夜 | 登録馬全頭でファイルを作る。騎手が未定なら `"jockey": "未定"` |
| 出走確定 | 木曜〜金曜 | 出走しない馬を外し、騎手・斤量を確定の値にする |
| 枠順確定 | 木曜〜金曜 | `umaban` を入れる |
| 当日 | 当日朝〜発走 | `odds`(実オッズ、`oddsKari: false`)・`weight`・`weightDiff`・`going`・`scratched` を更新 |
| 結果確定 | レース後 | `stage` を「結果確定」にし、`result` に1〜3着の馬名を入れる |

能力値(実績〜騎手)は、特別登録か出走確定のときに付け、そのあとは大きな変化(乗り替わり・取消・馬場悪化)があったときだけ直す。

## 3. JSONの形

```json
{
  "id": "kikkasho2026",
  "name": "菊花賞",
  "grade": "GI",
  "date": "2026-10-25",
  "place": "京都",
  "no": 11,
  "time": "15:40",
  "surface": "芝",
  "dist": 3000,
  "dir": "右",
  "courseNote": "外回り",
  "cond": "3歳牡・牝 馬齢57kg",
  "stage": "出走確定",
  "chaos": 8,
  "weather": "晴(予報・降水10%)",
  "going": null,
  "updatedAt": "2026-10-23T18:30:00+09:00",
  "source": "スポーツナビ競馬・JRA・tenki.jp",
  "memo": "出走馬確定。枠順は金曜に発表",
  "horses": [
    {
      "name": "ロブチェン", "jockey": "松山弘平", "style": "先行",
      "jisseki": 92, "kyori": 78, "course": 80, "choshi": 85, "kishu": 88,
      "heavy": 0, "odds": 2.8, "oddsKari": true, "umaban": null,
      "note": "皐月賞・ダービーの二冠。神戸新聞杯も勝利。3000mは初めて。"
    }
  ]
}
```

- `grade`: `GI` / `GII` / `GIII` / `J・GI` / `J・GII` / `J・GIII`
- `surface`: `芝` / `ダ` / `障`。`courseNote`: `内回り` / `外回り` / 空文字
- `going`: 芝(障害は芝)の馬場。0=良 1=稍重 2=重 3=不良。未発表は `null`
- `chaos`(波乱度・省略可): 16(ハンデ戦・2歳戦・新馬戦は20、障害は12)。2026-10-22に平場1,868レースで、オッズが出る前の1〜3着が一番当たる値に見直した(以前は8〜9.5で、人気薄の激走を少なく見すぎていた)。オッズを混ぜた後はほとんど影響しない
- `courseBias`(脚質ごとの加点。例 `{ "逃げ": 0, "先行": 1, "差し": 0.5, "追込": -1 }`)・`drawBias`(内枠の有利さ。0=なし、0.8=内枠がかなり有利、マイナスは外枠有利)は、判断材料ファイル(`馬情報/*_判断材料.md`)の過去10年の傾向から決めて必ず入れる。判断材料がまだ無いときだけ省略してよい(シミュレーターがコースの形から決める)
- 出走取消は、馬を消さずに `"scratched": true` を付ける

## 4. 能力値の付け方(各0〜100)

まずメンバーの中での順位を意識する。同じレースの中で差がつくように付ける。

重みは2026-10-22に平場1,868レースで当てはめ直した値(以前は実績35%・距離15%・コース15%・調子20%・騎手15%)。コースは当たりにほとんど効いていなかった。結果の記録が増えると optimize.pl が少しずつ動かす。詳しくは [的中率を上げるための検証.md](../馬情報/的中率を上げるための検証.md) の10

| 項目 | 重み | 基準 |
|---|---|---|
| 実績 `jisseki` | 28% | G1勝ち 90〜95 / G1で2〜3着・G2勝ち 85〜89 / G2・G3で2〜3着・G3勝ち 78〜84 / OP・L勝ち、重賞で掲示板 70〜77 / 3勝クラス勝ち 62〜69 / 2勝クラス以下 50〜61。2歳戦は、新馬・未勝利勝ち 65前後、1勝クラス・OP勝ち 72前後、重賞勝ち 82前後 |
| 距離 `kyori` | 17% | 同じ距離(±200m)で勝利・重賞好走 85〜90 / 経験があり好走 75〜84 / 未経験だが血統・走りから見込める 65〜74 / 大幅な延長・短縮で不安 45〜64。ただし距離短縮で初めての短距離(1400m以下)は不安扱いにせず 65〜74 とし、`choshi` +2([短距離戦の見方.md](../馬情報/短距離戦の見方.md)。全レースの自動計算も同じ) |
| コース `course` | 5.5% | 同じコースの重賞で好走 85〜 / 似たコース(小回り・直線の長さ・右左回り)で好走 75〜84 / 未知 65〜74 / 合わない 50〜64 |
| 調子 `choshi` | 24.5% | 前走勝ち・好時計・上昇中 85〜95 / 前走好走(5着以内) 70〜84 / 前走凡走 55〜69 / 大敗続き、または6か月以上の休み明け 40〜60 |
| 騎手 `kishu` | 25% | リーディング上位・G1常連(ルメール、川田、武豊、戸崎、坂井、松山、岩田望、横山武、短期免許の外国人トップ騎手など) 85〜95 / 重賞常連 75〜84 / 中堅 65〜74 / 若手・減量騎手 55〜64。障害は障害リーディングで同様に付ける |

- コース・ローテの規則性(詳しくは [競馬場の特徴_JRA10場.md](../馬情報/競馬場の特徴_JRA10場.md) の「コースを読む6つの規則性」)
  - `course`: 今回と同じ回り(右・左)で好走がなければ -5、好走が逆の回りに偏っていれば -8。平坦コースでしか好走がなく今回が急坂(中山・阪神・中京)なら -5
  - `course`: 好走した舞台と今回の舞台のタイプ(広さ・コーナー・坂・直線の長さ。4グループは競馬場の特徴_JRA10場.md)が違えば、その分を割り引く。例: 小回りで器用さを生かして好走 → 今回は大箱 -3
  - `course`: 1コーナーまでの距離の向き不向き。前走、同じ場の短い方(例: 中山芝1800)で届かなかった差し馬が長い方(中山芝2000)に出るなら +3、その逆で粘れなかった先行馬も +3
  - `jisseki`: 関西馬(調教師が栗東)の関東遠征は、それだけでは加点しない(2026年の重賞では人気どおりの成績で、オッズにもう入っている。[馬の走り方と調教.md](../馬情報/馬の走り方と調教.md) の検証)。前走までの好走が関東ローカル(新潟・福島)中心の馬が関西メイン(京都・阪神)の重賞に出るなら -3(人気になっていれば特に注意し、`note` に書く)
  - `choshi`: 前走が関西メイン(京都・阪神)の重賞で凡走でも、着差が小さく今回が格下の場なら、前走凡走の基準より +5 してよい
  - `drawBias`: 芝スタートのダート(東京ダ1600・中山ダ1200・阪神ダ1400・阪神ダ2000・京都ダ1400・中京ダ1400・新潟ダ1200・福島ダ1150)は外枠有利なのでマイナスにする。判断材料の馬番データと食い違うときは判断材料を優先する
- 危険な人気馬と巻き返し(詳しくは [危険な人気馬と単勝の狙い方.md](../馬情報/危険な人気馬と単勝の狙い方.md))
  - `choshi`: 前走逃げて好走 -2(同型がいれば -4)/ 半年以上の休み明け -9(通常の休み明けは -6)/ 前走道悪で好走して今回良馬場 -3(逆は +2)/ 芝で内枠→外枠、ダートで外枠→内枠で、前走好走 -3(逆の替わりで前走凡走なら +2)
  - `jisseki`: ダートで前走牝馬限定 → 今回牡馬混合の牝馬は -3(逆に、混合で負けて牝馬限定に戻るなら +2)
  - 前走4〜6着の馬は、前走1〜3着との差を付けすぎない(前走1〜3着は人気が出すぎやすい)
  - `choshi`: 1〜5番人気の前走2着は -2(人気しすぎ。全レースの自動計算と同じ。[単勝の買い方_コタ.md](../馬情報/単勝の買い方_コタ.md))
  - 近走で勝ちがなく2・3着を繰り返す馬は `note` に「善戦型」と書く(能力値は動かさない。1〜3番人気なら予想の文章で「単勝の軸にしない」と出る)
  - `choshi`: 着順だけでなく着差も見る。4着以下でも勝ち馬と0.3秒差以内なら +4、2〜3着でも1秒以上離されたら -4。負けた相手が強かったか(勝ち馬のその後)も見る
  - `jisseki`: タイム指数を使うときは近走の平均ではなく最高値で力の上限を見て、1〜2の差は同じとみなす
  - 2・3着が極端に少なく、勝つか大敗かの馬は `note` に「勝つか大敗か」と書く(単勝向き)
  - G1の1〜3番人気: 前走が自己最高の内容(過去のG1好走より上)なら `note` に「反動」、同じ上位の馬に何度も負けて勝負付けが済んでいるなら「勝負付け」と書く。能力値は動かさず、予想の文章の「G1の荒れ方」に使われる([G1の高配当パターン.md](../馬情報/G1の高配当パターン.md))
  - 3連勝以上の馬: `note` に「N連勝」と書き、勝ったレースが恵まれていたか(メンバー・展開・ペース)を一言添える。1番人気なら不安材料に「N連勝中」が出る(能力値は動かさない。[危険な1番人気_連勝とトラックバイアス.md](../馬情報/危険な1番人気_連勝とトラックバイアス.md))
  - G1の1〜3番人気: 過去走から自動で見られない危険なサイン(馬場・枠の不利、そもそも強くない、普通に考えて来ない、古い年のG1成績で分かる「惜しい競馬の繰り返し」「リピーター」など)は `"g1Danger": ["理由"]` に書く。距離適性・G1の格・リピーター・惜しい競馬・急激な衰え・前走人気薄で激走・断然人気がいるときの2・3番人気は馬カードの過去走とオッズから自動で見る。2つ以上で「危ない」。能力値は動かさない([G1の危険な人気_10パターン.md](../馬情報/G1の危険な人気_10パターン.md))
- 使わない情報(ノイズ。詳しくは [予想で捨てる情報.md](../馬情報/予想で捨てる情報.md))
  - `kishu`: 数年分の成績で条件ごとに差がはっきりしている騎手は [騎手の得意・苦手.md](../馬情報/騎手の得意・苦手.md) で調整する(例: ルメールは芝1200m前後・追込・高齢馬で下げ、東京芝2400mで上げる。ほかに高杉吏麒・田辺裕信・西村淳也・今村聖奈・幸英明・丹内祐次・松山弘平・北村友一・坂井瑠星・横山典弘・津村明秀・三浦皇成・武豊。追込馬に西村淳也・丹内祐次、芝1200mに田辺裕信、1番人気の幸英明は下げる)。**「7人の癖」(騎手の得意・苦手.md)は ±2 までで付ける**: ルメールは稍重〜不良で -2・芝2000m以上の重賞と8枠では下げない、川田は芝2500m以上で -3・小回り芝2000m重賞と阪神京都の芝1600mの先行馬で +2、戸崎は外枠(特にダート)で +2・内枠の差し馬で -1、坂井は差し馬で -1・500kg以上で +1、松山はG2の先行馬で +2・外枠の差し馬で -1、岩田望は阪神京都・ダートで +2・東京で -2(乗り替わりでは下げない)、西村淳は杉山晴・中内田厩舎とロードカナロア産駒で +2・関東のダートで -2。枠順で決まるもの(外枠・内枠)は枠順確定のときに直す
  - `kishu`: 全レースの自動計算(race_json.pl)は、騎手のこのコース連対率に加えて、調教師×騎手連対率(10回以上で40%以上 +3・30%以上 +2・15回以上で5%以下 -2)、追込の馬に追込が苦手な騎手(西村淳・丹内 -3、ルメール・坂井・松山・幸 -2)、牝馬(今村 +2・北村友 -2)、7人の癖(ルメールの道悪 -2、戸崎のダート外枠 +2・内枠の差し追込 -1、坂井の差し -1・500kg以上 +1、松山の外枠の差し追込 -1、西村淳のロードカナロア産駒 +2)で補正する(合計±5まで)。重賞を手で付けるときも同じ考え方で見る
  - `kishu`: 騎手の「最近の調子(ここ数週の勝ち星)」では上げ下げしない。乗り替わりの強化・弱化もオッズに織り込まれるので、基準どおりに付けるだけにする。例外: 以前その馬で好走した騎手に戻る(手戻り)なら +3
  - 馬体重: 増減だけでは動かさない(大きく動くと嫌われてオッズが上がり、単勝回収値はむしろ高い)。割り引くのは -20kg以上(`choshi` -4)・2〜3歳のマイナス2桁(-2)・夏や滞在競馬(北海道・小倉)での減少(-1)・6歳以上の+10kg以上(太め残り -2)だけ。2〜3歳の増加は成長として減点しない。大きく増減したときは、好走したときの馬体重に近いかを見て `note` に書く(近ければ心配いらない)。長距離輸送で減るタイプかも過去の遠征で確認する。休み明けの大幅増でも、休み前に減り続けていたなら「戻しただけ」として減点しない
  - 馬格: 大きい馬ほど成績が良い(400kg未満の複勝率約7%、500kg台は約25%)。`jisseki` を 420kg未満 -2・500kg以上 +1
  - 当日のパドック解説・SNSの評判では能力値を変えない。パドックを使うのは「入れ込むと走らない馬」など、その馬の過去のパドックと結果から事前に決めた条件に当てはまったときだけ
  - 他人の予想(予想サイト・SNS・YouTube)の印や買い目は能力値に入れない。参考にするのは、その結論に至った理由(展開・適性の見立て)だけ
  - 調教: 「好時計」「絶好調」だけでは上げない(2026-10-26 検証: 重賞120レース・833頭で、同じレースの中での時計・終い1F・併せ/単走・坂路/ウッド・加速ラップはどれもオッズ以上に当たらなかった。[的中率を上げるための検証.md](../馬情報/的中率を上げるための検証.md) の14)。その馬のこれまでの追い切りと比べてはっきり良い・悪いときだけ `choshi` ±2(新馬戦の加速ラップ +3 は別)。美浦の坂路は2023年10月に改修されたので、それより前の時計とは比べない([馬の走り方と調教.md](../馬情報/馬の走り方と調教.md))。見るのは時計より本数と強さ、いつものパターンとの違い([調教の見方.md](../馬情報/調教の見方.md)):
    - -2: 休み明けで前回の休み明け好走時より本数がはっきり少ない / 本数が少なく全部馬なり / いつものコース(ウッドなど)から急に坂路中心になり、故障明けなど理由が考えられる
    - +2: 近走は不振でも本数が増えて強めの内容が続く / 故障明けで坂路中心だった馬がいつものコースに戻した
    - 動かさない: ほかの馬との時計の比べ合い / ポリトラック(P)の好時計 / 1週前に強めで当週が軽い(その厩舎のいつものパターンなら)
  - 前走の中身: 着順より、メンバーの強さ・ペース・位置取りを見る。スローペースを2番手で楽に残しただけの好走は `choshi` -2、ハイペースで外を回されながら着差が小さい凡走は +2(着差の補正と合わせて±5まで)
  - 前崩れのレース([穴馬の激走パターン.md](../馬情報/穴馬の激走パターン.md)): 前走が差し・追込で上位独占の前崩れで、前半が速いラップの裏付けがあり(高速馬場で数字だけ速いのは除く)、そこを先行して4〜10着に粘った馬は `choshi` +2、`note` に「前走ハイペースを先行して粘った」。スローの瞬発力勝負で飲み込まれた先行馬は上げない。崩れた先行馬が人気馬ばかりなら差し有利の展開だった裏付けになる。全レースの自動計算は2勝クラス以上・前走H・1角と4角3番手以内・4〜10着で +2
  - 東京→中山: 前走東京で3着以内の馬が中山で人気なら `choshi` -2(適性が逆。特に年末の5回東京ダートの好走馬が12月の中山ダート)。前走東京ダートで凡走した馬の中山ダートは +1。全レースの自動計算も同じ
  - 前走の映像([レース映像の見方.md](../馬情報/レース映像の見方.md)): 4コーナーで推進力があり、直線前半まで持ったまま(東京なら残り400m付近まで)だったのに負けた馬は `choshi` +2。スローペース・逃げ馬・ダートの4コーナーは手応えが良く(ダートは悪く)見えやすいので動かさない。馬場の良いところ(内有利の日の内ラチ沿い、千直の外ラチ沿いなど)を通って好走した馬が今回フラットな条件で人気なら -2 とし、`note` に「馬場の恩恵」と書く(1番人気の不安材料に出る)。逆に悪いところを通って負けた馬は +2。千直の外枠で好走した馬は全レースの自動計算でも -2
  - ローテーションのレベル: 前走の上位馬がその後勝ち上がっている・同じレースの出走馬が次走で好走しているなど、前走がハイレベルなら、着順が悪くても `choshi` +2まで戻し、`note` に「前走ハイレベル」と書く。上位2頭に票が集中したレースでは、こうした人気薄が大穴の軸候補になる([馬券の買い方_大穴軸の3連複.md](../馬情報/馬券の買い方_大穴軸の3連複.md))
- ダート(詳しくは [ダートの見方.md](../馬情報/ダートの見方.md))
  - 前の馬の砂をかぶるかを見る。内枠の差し・追込で、過去に内枠で砂をかぶって凡走しているなら `choshi` -2。内枠でも、通過順・前半3ハロン・スタートのうまさでダッシュ力があると分かる逃げ・先行は減点しない
  - 3勝クラス・オープン・重賞では先行争いが激しくなるので、内枠や馬群の中で砂をかぶっても好走したことがある差し馬は `choshi` +2
  - 道悪は砂が舞わずスピードが出るので、芝でも走れる血統・スピード型を `heavy` で +1 寄りにする。良馬場はパワー型
  - 中京ダ1800は例外で内枠有利(シミュレーターのコース別の設定に入っている)
  - 前走芝で今回ダートの外枠の馬が、過去のダートで先行して好走しているなら `choshi` +2(砂をかぶらずに前へ行ける。[大外枠が激走する条件.md](../馬情報/大外枠が激走する条件.md)。全レースの自動計算にも入っている)
- 芝の上級条件(3勝クラス以上)×右回りの長距離で、逃げ・先行・まくりの馬が半数近くいるときは、展開を `high` 寄りに見て、後方でためる外枠の差し馬を外枠という理由だけで割り引かない(点数は付けない。手元の検証では裏付けがない)
- 2歳戦・キャリアの浅い馬(詳しくは [新馬戦の見方.md](../馬情報/新馬戦の見方.md))
  - `choshi`: 1〜3月生まれ +3、6月以降生まれ -3(`profiles` の `birth` で確認)。最終・1週前追い切りが加速ラップなら +3
  - `jisseki`: 新馬戦は、ダート500kg以上 +3・460kg未満 -3、芝460kg未満 -2。兄姉がJRAの新馬戦で好走していれば +2
  - `kishu`: 新馬戦で成績の良い騎手×調教師のコンビなら +3
  - 脚質: 新馬戦で戦績がないときは、陣営コメントの「スタートが速い」「前向きな気性」で `先行` にする(新馬戦は前が有利)
- 血統の国別タイプ(詳しくは [血統の系統と国別タイプ.md](../馬情報/血統の系統と国別タイプ.md))
  - 2・3歳限定の新馬・未勝利・1勝クラスのダート1400m以下で父が米国型なら `course` +2(全レース自動計算も同じ)
  - 古馬混合の芝2200m以上で、父か母父が欧州型・道悪の経験2戦以下なら道悪で `heavy` +1(全レース自動計算も同じ。手で付けたレースでも `heavy` が0なら、シミュレーターが馬カードの血統から自動で足す)
  - 雨で重い芝でも、小回り・直線が短く前残りになりそうなとき(福島芝2000mの重賞など)は、母父が米国型の馬を `heavy` +1 寄りにする(手で付ける)
  - 直線が短く坂があり上がりがかかるコース(中山金杯・福島牝馬Sなど)では、サドラーズウェルズ系・ロベルト系を持つ人気薄を `note` に書いて穴の候補にする(手で付ける)
  - 当日の芝で日本型(サンデー系)の父の馬が来ているかは自動で補正する(当日バイアスの `dayBias.jp`。反主流の日は日本型を下げ、欧州型・米国型を上げる)。手で能力値を動かさない
  - タイプは [種牡馬_国別タイプ.tsv](../馬情報/種牡馬_国別タイプ.tsv) で引く。手で付けるレースは、出走馬ファイルの一覧表に「父」「母父」の列を入れておく(馬カードの血統になり、シミュレーターがタイプを引く)。自動計算のレースは `sire`・`damsire`・`sireType`・`damsireType` が入る
- 展開の目印(省略可、詳しくは [展開予想の手順.md](../馬情報/展開予想の手順.md)): 近3走で2回以上1角先頭の「逃げないと走らない馬」は `"mustLead": true`、前走より200m以上の延長で逃げ・先行の馬は `"fromShort": true`。シミュレーターのペースの自動見積もりに使われる。`mustLead` の馬自身も、ハイペースの回は -1.5、スローの回は +1 される。前走の最初のコーナーで3番手以内なら `"prevFront": true`、それ以外は `false`(前走が古い・分からない馬は書かない)。7割以上の馬に書くと「展開と隊列」に割合が出る。30%未満なら前走より200m以上の延長の馬を `choshi` +1、40%以上なら -2 して note に「距離延長・前に行く馬が少なく落ち着きそう(+1)」のように書く(全レース自動計算も同じ)
- 軸の減点(省略可、[軸馬と相手の選び方.md](../馬情報/軸馬と相手の選び方.md)): 1〜3番人気に `"axisCheck": [{"why": "6か月以上の休み明け", "pt": -3}, …]` を書くと、予想の文章の「軸の減点」にそのまま出る(書かなければ note・馬番・馬体重・脚質から分かる項目だけ自動で見る)。能力値には足さない
- ラップの型([ラップの見方.md](../馬情報/ラップの見方.md)): 芝1600m以上で、好走が持続力勝負(中山・阪神内回り・ローカル)だけで瞬発力勝負(東京・外回り)で凡走している馬が、今回瞬発力勝負のコースなら `choshi` -2(逆も同じ)。実際のラップで型を確かめて `note` に書く。全レースの自動計算はコースの形で同じ判定をしている
- 脚質 `style`: 近3〜4走の4コーナー通過順で決める。ほぼ先頭=`逃げ`、頭数の前3割=`先行`、中団=`差し`、後方3割=`追込`
- 重馬場 `heavy`: 道悪で勝ち・好走 +2 / やや得意 +1 / 不明・普通 0 / やや苦手 -1 / 道悪で大敗 -2。道悪の経験が2戦以下なら、父の道悪適性([種牡馬の道悪適性.md](../馬情報/種牡馬の道悪適性.md))で ±1 する(全レース自動計算も同じ)
- 仮オッズ `odds`(`oddsKari: true`): 実績と前評判から人気を想定して付ける。全頭の(1÷オッズ)の合計が1.26前後になるようにする。実オッズが出たら置き換えて `oddsKari: false`
- 根拠 `note`: 能力値の根拠を1〜2文(主な実績・前走・不安点)。人気薄(仮オッズ・実オッズで10番人気以下)も後回しにせず、同じ手間で好走の要素(過去に好走した条件・血統・得意な馬場・騎手との相性)を探して書く。穴馬は印のない馬から出る

## 4-3. ニュースの使い方
毎日 朝・昼・晩に集めているニュース(db `news`、`馬情報/ニュース/YYYY-MM-DD.md`。手順は [自動実行/ニュース/手順.md](../自動実行/ニュース/手順.md))は、レースデータを作る・直すときに必ず見る。そのレースの `raceIds` が付いた記事と、出走馬の名前が `horses` にある記事を読む。
- 使う: 出走取消・回避(`scratched`)、想定騎手・乗り替わり(`jockey` と `kishu`)、予想オッズ(仮オッズの置き換え)、新しく登録された馬、故障・出否未定(`choshi` -5〜-10)、馬場・天気
- 条件付きで使う: 追い切り・状態の記事は、その馬のこれまでと比べてはっきり良い・悪いときだけ `choshi` ±2(上の「調教」の決まりと同じ)。次走予定は、まだシミュレーターにないレースの特別登録の参考にする
- 使わない: 記者・予想家の印や推奨馬、関係者の「自信」「順調」といったコメントだけ(`note` に書くのはよい)
- ニュースから直した値は、`note` に「(ニュース 10/20)」のように日付を付けて書く

## 4-2. 馬カード用のデータ(`profiles`)
シミュレーターで馬名を押すと開く「馬カード」(血統・戦績)は、次の2つから作られる。
- ページと一緒に公開している `data/profiles.json`(PCで `シミュレーター\build_profiles.ps1` を実行すると、「馬情報」の `*出走馬*.md` と重賞の全着順から作り直せる。反映にはシミュレーターの再公開が必要)
- レースデータの `profiles`(下の形)。ここに書けば再公開なしでカードに出るので、出走馬ファイルを作ったら必ず付ける

```json
"profiles": {
  "ドリームコア": {
    "sexage": "牝3", "trainer": "田中博康(美)", "sire": "キズナ", "dam": "ノームコア", "damsire": "ハービンジャー",
    "birth": "2023-02-05", "owner": "吉田勝己", "breeder": "ノーザンF", "record": "7戦3勝[3-1-2-1]", "prize": "1億3240万",
    "comment": "重賞は桜花賞以外すべて3着以内",
    "runs": [
      { "date": "2026-09-06", "race": "紫苑S", "grade": "GII", "place": "中山", "surface": "芝", "dist": 2000,
        "rank": 3, "heads": 11, "pop": 1, "odds": 2.5, "jockey": "ルメール",
        "weight": 502, "weightDiff": 4, "time": "2:03.8", "pass": "4-4-5-3", "f3": 36.7 }
    ]
  }
}
```
- キーは馬名(`horses` の `name` と同じ表記)。分からない項目は省く。`runs` は新しい順で、近3〜5走
- 騎手カード(騎手名を押すと開く)は、`2026重賞_全着順.csv` から集計する。CSVを更新したら `build_profiles.ps1` を実行して再公開する
- 秋華賞(`shukasho2026`)のように `update` で書くレースでも、`profiles` は `horses` と別の項目なので、自動更新で消えない

## 4-4. 一獲千金(`ikkaku`、重賞だけ)
シミュレーターの「一獲千金」タブに出す、Claudeの渾身の 3連単・3連複・馬単・馬連(2026-10-25 ユーザー指示「重賞以上のレースで人気、実力だけではなくすべての要素を取り入れ渾身の買い目を」)。
- いつ書く: 枠順が確定したら書く。当日の朝(馬場・オッズ)と、馬体重・取消が出たら見直す。特別登録の段階では書かない(枠が大事な材料なので)
- 何を見る: 判断材料ファイル(過去10年・コース・馬番・前走・騎手・血統・各動画の見方)、追い切り、ニュース、当日の馬場・天気・馬体重、単勝オッズ、シミュレーターの勝率。人気と能力値だけで決めない。一獲千金なので、データの型(例: 1番人気の2着が少ない・前走4着以下は来ない・外枠有利)から人気馬が崩れる形・人気薄が来る形を探し、軸と相手を決める
- 形: 他人の印は理由にしない(事実とデータだけ)。点数は予算3000円(100円単位)で収まる20〜25点まで。`share` の合計は1(券種ごとの予算の割合)
- 取消・除外の馬が入る組はページが自動で外すが、次の更新で書き直す

```json
"ikkaku": {
  "at": "2026-10-25T08:10:00+09:00",
  "basis": "10/25 7:53のJRAオッズ・枠順確定後の判断材料",
  "title": "ルメールの上がり馬が2冠馬を差す",
  "story": "なぜこの形で買うか(人気馬が崩れる理由・穴が来る理由)を数行で",
  "factors": [ { "k": "人気(オッズ)", "v": "…" }, { "k": "騎手", "v": "…" }, { "k": "枠・コース", "v": "…" } ],
  "bets": [
    { "type": "3連単", "share": 0.3, "legs": [["1着の馬"], ["2着の馬", "…"], ["3着の馬", "…"]], "why": "…" },
    { "type": "3連複", "share": 0.3, "box": ["馬", "馬", "馬", "馬"], "why": "…" },
    { "type": "馬単", "share": 0.2, "legs": [["1着"], ["2着", "…"]], "why": "…" },
    { "type": "馬連", "share": 0.2, "legs": [["軸"], ["相手", "…"]], "why": "…" }
  ],
  "note": "発走前に確かめること"
}
```
- `type`: `3連単` / `3連複` / `馬単` / `馬連`。同じ券種を2つに分けてもよい(例: 人気馬が残る形と崩れる形)
- `legs`: 着ごとの馬名(フォーメーション)。馬連・3連複は着順を問わず、同じ組は1つにまとめる。`box` は全着に同じ馬を並べたもの
- `factors` の `k` は 人気(オッズ)・実力(能力値)・騎手・枠・コース・前走・ローテ・馬体重・展開・血統・馬場・リスク などから、効いたものを書く
- ページは券種ごとに予算を `share` で分け、同じ券種の中は同額。予算が足りないときは、シミュレーターの的中率が高い組から残す
- `races/<レースID>.json` にも同じ `ikkaku` を入れておく(`set` で書き直したときに消えないように)

## 5. シミュレーターへの書き込み
- ArtifactData を使えるときは、`url: https://claude.ai/artifact/P8QScqCpR36cPEkxMtou9s`、`collection: races`、`doc_id: <レースID>` に、JSONファイルの中身を書く
  - 新しいレース: `set`(`if_version` なし)
  - 既存のレース: 先に `get` して `version` を確認し、`set` に `if_version` を付ける
- 使えないときは、JSONファイルの保存だけでよい(PC側の同期のときに書き込まれる)
